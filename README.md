**Onesimus** ('helpful') is my Vim-first, portable editor distribution
for human agents.

I made it for both daily development and academic production: code, Markdown,
TeX, and the awkward little tasks for which Vim is still the nicest place to
be. I use other editors now, but this is still the one I want to carry onto an
ordinary server.

Convention over configuration still matters here. Native Vim is the common
denominator. Plugins should appear only when their context asks for them and
remain replaceable behind a small, stable set of Onesimus actions. It should be
quiet before it is clever—and, where that costs nothing, not only usable but
aesthetically amusing.

The long `:Onesimus...` commands are scripting entrypoints. Normal use is
smaller: familiar Vim motions, F2–F6, Home, and the action guide.

## What is included

- One language-tooling surface through ALE: LSP, diagnostics, linting,
  completion, and formatting
- Fuzzy finding through Clap, asynchronous jobs, and Git integration
- Markdown, TeX, a plain-text writing mode, and CJK-aware prose editing
- Lazy loading for Clap, NERDTree, focus mode, and Chinese word segmentation
- A compact Home screen and a strictly local feature-adoption journal
- Stable project roots for ALE, Clap, Fugitive, and `:make`

There is deliberately no bundled AI client. Those tools can live beside Vim
without becoming a condition for using it. The old Literate Programming
ambition is deliberately smaller too: `<F4>` remains a practical terminal
REPL, not the beginning of an embedded notebook system.

## Requirements

- Vim 8.2 or newer, with `+job`, `+channel`, `+timers`, and `sha256()`
- Git and curl for installation and plugin bootstrap
- Optional: a Vim build with `+python3` for Chinese word segmentation
- Optional language tools such as language servers, linters, formatters,
  compilers, and `ctags`; Onesimus reports what is available instead of
  installing system-wide tools

Neovim is welcome to work, but it is not a design target or part of release
verification. Vim 8.2 is the contract.

### macOS GUI

MacVim is an optional native companion, not a separate editor configuration.
Both terminal and GUI entrypoints load the same Onesimus setup:

```sh
vim file       # stay in the current terminal or SSH session
mvim file      # open a native macOS window
open -a MacVim file
```

Install the signed application with `brew install --cask macvim-app`. To use
that same application for terminal Vim too, link `vim` to
`/Applications/MacVim.app/Contents/bin/mvim` instead of maintaining a second
Vim installation. Finder's **Open With**, drag-and-drop, and native tabs then
use the same plugins and editing state. This is a local convenience; the
portable terminal contract remains unchanged.

## Installation

### New installation

```bash
curl -fsSL -o /tmp/onesimus-install.sh \
  https://raw.githubusercontent.com/BaksiLi/Onesimus/master/install.sh
bash /tmp/onesimus-install.sh
```

The default checkout is `~/vimrc`. Existing `~/.vimrc` content is preserved as
a timestamped `~/.vimrc.onesimus-backup.*` before Onesimus installs its small
loader. Use `--root /another/parent` to place the checkout elsewhere, or
`--no-launch` to install only the core and defer plugin synchronization.

### Updating an existing installation

From Vim, choose `u  Update` on the Home screen, or press `<Leader>`, then
`o`, then `u`. The equivalent command is `:OnesimusUpdate`. It updates in the
background and posts a non-blocking restart notice when the on-disk
configuration and plugins are ready; the running process is never
half-reloaded.

From a shell, run the installer inside the checkout:

```bash
~/vimrc/install.sh --update
```

An installed copy discovers its own checkout, so the same command works from a
custom location without repeating `--root`. The updater:

- refuses tracked local changes instead of stashing, resetting, or merging
  them;
- follows the current branch's configured upstream, preserving forks, custom
  remote names, and SSH URLs;
- serializes updates per checkout, uses a private installer copy, bounds only
  the network fetch, and then fast-forwards locally before the new installer
  finishes the migration;
- migrates only loaders generated by Onesimus/Onesimos; an update never
  replaces a user-managed `.vimrc` or symlink;
- saves the actual installed plugin revisions, attempts a non-blocking vim-plug
  self-update, then synchronizes declared plugins and their native artifacts
  to the reviewed revisions in `plugins.lock.json` with `PlugUpdate --sync`;
- leaves undeclared plugin directories untouched, because an automatic
  `PlugClean!` could delete plugins managed by the user.

Use `--core-only` when deliberately updating the configuration without touching
plugins. A plugin-network failure does not roll the core back; fix the network
and repeat `install.sh --update` to finish synchronization. Review retired
plugin directories interactively with `:PlugClean` before approving deletion.

Plugin snapshots live under `$XDG_STATE_HOME/onesimus/plugin-snapshots`
(default `~/.local/state/onesimus/plugin-snapshots`). They are kept across
updates. `:OnesimusPluginSnapshot` also saves one explicitly; an optional new
filename selects another destination. To restore installed remote revisions,
`:source /path/to/snapshot.vim` in Vim with Onesimus loaded. Snapshots record
actual Git HEADs even when they differ from the lock, and note local checkouts
and tracked changes; they do not restore uncommitted files or modify local
development checkouts. A later normal update reapplies the distribution lock.

Maintainers update `plugins.lock.json` deliberately after reviewing and testing
new revisions. Personal `Plug` declarations load after the distribution's
pins and can select another revision or fork.

Installations made by Onesimos 0.1.x do not yet understand `--update`. Bootstrap
their one-time migration with the current installer:

```bash
curl -fsSL -o /tmp/onesimus-install.sh \
  https://raw.githubusercontent.com/BaksiLi/Onesimus/master/install.sh
bash /tmp/onesimus-install.sh --update
```

Add `--root /the/original/parent` only when that legacy checkout was installed
outside `~/vimrc`. The old loader is backed up, a historical `vimrc.backup`
inside the checkout is preserved, and the exact official Onesimos remote is
migrated to the Onesimus URL. A locally edited legacy `custom/plugins.vim` is
also preserved byte-for-byte and converted into an ignored personal file.
Other remotes and tracked modifications are never rewritten.

If a legacy fork has not yet merged the current installer, the migration stops
after its attempted fast-forward and before touching `.vimrc`. Update that
fork from Onesimus, then run the same command again; the updater never executes
an old interactive installer as a handoff target.

## Keymaps
The default leader key is `\`.

Press `\` and pause for global tools.
Press `\\` for the current file's actions; `\.` also opens them directly.
Neither menu exposes the full internal command surface.

### Core Navigation
- `<leader>ed` - Edit dotfile
- `<leader>sd` - Reload dotfile
- `<leader>?` - View help document (`<leader>h` remains an alias)
- `<leader>.` - Current-buffer action guide
- `<C-J/K/H/L>` - Navigate between splits
- `]b/[b` - Next/previous buffer
- `]c/[c` - Next/previous quickfix item

### IDE Features
- `<leader>ff` - Fuzzy find files (vim-clap)
- `<leader>fb` - Fuzzy find buffers
- `<leader>ft` - Fuzzy find tags
- `[d/]d` or `[a/]a` - Previous/next diagnostic
- `<leader>ld` - Open diagnostics for the current buffer
- `<leader>li` - Show concise tool status in a popup
- `<F2>` - Search symbols/tags in the current buffer
- `<F3>` - Toggle file tree (NERDTree)
- `<F4>` - Open REPL
- `<F5>` - Conflict-check, save, then run/build the current context
- `<F6>` - Format current file
- `<leader>oh` - Open Onesimus Home
- `<leader>os` - Open the local usage dashboard

### Editing
- `lkj` - Alternative to Escape
- `<leader>tr` - Toggle relative numbering
- `<leader>tp` - Toggle rainbow parentheses
- `<leader>ti` - Toggle indent lines
- `<leader>tw` - Toggle focused writing mode
- `<leader>tb` - Toggle light/dark background
- `gd/gr` - Go to definition/find references when an LSP is connected
- `<leader>. g` - Open the contextual symbol-navigation menu for definition,
  references, implementation, and type definition
- `K` - Hover documentation when a language server is connected
- `gs/gS` - Buffer/workspace symbols
- `<leader>rn` - Rename symbol (LSP)
- `<leader>ca` - Code action (LSP)
- `:ALEInfo` - Open advanced provider diagnostics when the concise status is
  not enough

Haskell is biased toward reading code and validating small changes. With HLS
installed, ALE supplies diagnostics, completion, hover, navigation, rename,
and code actions. `<F5>` checks the nearest Stack or Cabal project; outside a
project it asks GHC to typecheck the current file without generating code.
`<F6>` follows a project `fourmolu.yaml`, `.ormolu`, or
`.stylish-haskell.yaml`; without a declared policy it prefers Ormolu, then
Fourmolu, then Stylish Haskell. If none is installed, formatting degrades to
safe whitespace cleanup and `<leader>li` explains what is missing. Onesimus
never installs or selects a system-wide Haskell toolchain on the user's behalf.

### TeX workflow

Press `\` for global tools and `\\` for the current file.
In a TeX buffer:

| Keys | Action |
| --- | --- |
| F5 or `\\b` | Save safely, build, then open the PDF after success |
| `\\v` | Open/reuse the browser preview; locate the cursor when the build is current |
| `\\d` | Build a latexdiff revision PDF against the chosen baseline, or HEAD |
| `\\s` | Save text only |
| `\\t` | Outline / sections |
| `\\e` | Compilation errors |
| `\\n` | Review sentence-based source lines without saving |
| `\\w` | Manuscript word count |
| `\\z` | Toggle focus mode |
| `\\o` | Less frequent tools, build modes, reader URL and project details |

Use the displayed keys, arrows plus Enter, or taps when the terminal passes mouse events through.
Left / Backspace returns to the parent menu.
Progress and results share one notification; previous output stays in `:messages`.

F5 safely saves and builds, then opens the browser preview on every platform.
A failed build reports errors without opening a reader.
More tools offers build-only, live builds, the session URL, and an external PDF opener.
Viewing never saves or builds; unsaved edits are absent from that PDF.
Live builds watch explicit saves and reuse the reader without repeatedly bringing it forward.
F5 reuses a page that is still checking the session; it opens the existing URL only when no page is present.
`\\v` explicitly opens that URL, including after a tab was closed or suspended.
Preview and other native readers are external openers only; Onesimus does not manage their refresh.

A build checks all loaded sources belonging to the paper, including shared bibliography files outside its directory.
Other dirty sources must be reviewed and saved first; F5 does not save every buffer.
Changes to the root, includes, bibliography declarations or preamble refresh VimTeX's project state on save.
Background results stay attached to their project when you switch papers.
`PDF OUTDATED` means tracked inputs changed after, or during, the successful build.
This is freshness feedback, not a reproducible snapshot of concurrently edited files.

Human–Harness collaboration uses the same rules regardless of who writes the file.
Clean writing buffers (TeX, BibTeX, Markdown, plain text and Cogitatum),
including hidden ones, refresh automatically when editing is interruptible.
Cursor and viewport positions follow matching source passages where possible.
Insert mode and Visual selections defer replacement.
Identical local and disk revisions become clean without a false conflict.
When both sides differ, the draft stays in memory and saving is blocked.
The menu then shows comparison and explicit resolution actions directly.
A later disk change invalidates a prior review.
Normal writes retain private Vim backups; reviewed resolution snapshots the disk version before replacing it.
These checks cannot provide an atomic filesystem compare-and-swap against another writer.
Use separate Git worktrees for independent concurrent changes.

Formulas render in place through [texinsitu.vim](https://github.com/BaksiLi/texinsitu.vim),
declared in `custom/plugins.vim` (see `plugins.vim.example`). In TeX, Markdown
and Cogitatum source, entering a formula reveals its TeX and leaving it shows
the rendering again; yanks, saves and undo always operate on source. `\\m`
switches the buffer between rendered formulas and raw source. Onesimus turns
off VimTeX and Markdown syntax conceal so the plugin is the only formula layer;
the browser PDF remains the full TeX rendering.

Counted line jumps, search, quickfix and tag jumps open folds around their target.
Entering Insert opens the edited fold; ordinary vertical movement leaves closed folds alone.
Soft wrapping keeps the `↳` continuation mark and does not insert source newlines.

#### Browser PDF and mobile terminals

Use `\\d` or `:OnesimusDiff [snapshot|git-ref]` to build a **latexdiff revision PDF**.
With no argument it reuses the chosen baseline, reads `<main>.review-base` beside the
main source, detects `<main>.base.tex`, or compares with `HEAD`. The adjacent conventions
also prepare Changes during ordinary preview without switching away from Original.
Relative sidecar paths resolve beside the main source.
An explicit snapshot path resolves in Vim's current directory. A file snapshot should keep
its included chapter files beside it; a Git baseline retrieves historical TeX sources,
including chapters removed or renamed since that revision.

The browser offers **Original / Changes** in the same session. Changes is a separately
compiled PDF: added text is blue and underlined, deleted text is red and struck through,
and changed display equations are marked as whole equations. Figures use current assets;
this does not compare image contents. The previous source-line overlays and deletion
comments are removed.

Comparison runs in a private temporary directory using the project's source files and
TeX engine. It never saves buffers or replaces the manuscript's PDF. Save and build with
F5 first if the sources are modified or outdated. Once a baseline is chosen, later successful
F5 builds refresh the comparison in the background. An explicit OnesimusDiff switches to
Changes when ready; F5 preserves the version you are reading. Each version retains its own
page position and zoom. **Download changes PDF** exports the revision for sharing.

A failed comparison preserves Original and the last complete revision; its explanation
identifies the baseline of the retained revision. **More options → Comparison log** shows
the build output. Both versions support **Locate in source** and PDF-text-to-Visual navigation.
Changes maps generated SyncTeX positions back to the manuscript. Removed or unmatched
passages locate nearby surviving source with a notice; ambiguous mappings never open
generated or historical files. An explicit cursor
locate returns to Original; optional cursor following leaves Changes undisturbed.
Comparison jobs and temporary files end with the Vim-owned reader. There is no second
browser session or persistent comparison server. The host needs `latexdiff` and `latexmk`.

For **Termius → Zellij → Vim**, use F5 to build and open the browser, or `\\v` to read the existing PDF.
Vim displays the reader URL; **More tools → Preview session URL** shows it again.
Remote access uses SSH port forwarding or a privately configured relay hostname.
Set `g:webpreview_host` locally before sourcing Onesimus when a relay is used;
the default stays on loopback. The relay must route to the displayed loopback port.
Hostnames and session URLs belong in your local configuration, not shared docs.

Each Vim owns one reader with its own port and private URL.
Reopening the same paper reuses it; switching papers replaces it.
Zellij detach preserves the session; exiting Vim, including a crash, ends the reader.
Old links expire with their Vim session.
There is no background daemon or shared session registry.
`:OnesimusTexBrowserStop` stops it explicitly.
The server stays on loopback and exposes the PDF and bundled viewer assets, without serving source files.

The browser uses locally bundled PDF.js and keeps page position and zoom across PDF refreshes and page reloads.
Auto refresh is on by default; **More options (⋯)** holds its switch and
**Download PDF**. Turn automatic refresh off when comparing a revision.
Selecting text pauses replacement.
Cmd-F / Ctrl-F searches PDF text; Enter and Shift-Enter move between matches,
and Escape closes search and returns focus to the PDF. The **Find** button
provides the same entry on touch devices, at the right of the toolbar. **Back** returns after an internal citation jump.
**Fit** toggles continuous page-width fitting; manual zoom turns it off. Each PDF version
keeps its own position and zoom. A single PDF status shows build, comparison and refresh state;
press it for details or to load a waiting PDF. **Original / Changes** is one version switch.
To return to Vim, press **Locate in source**, then tap a place in the PDF.
Or select PDF text and press **Select in source**: Vim enters characterwise Visual only when
that text has a unique literal match in the located source paragraph, allowing whitespace changes.
TeX macros, formulas, ligatures, and changed drafts can prevent a match; then Vim locates the passage and explains.
The target fold opens automatically. Insert, Visual and command-line input defer source jumps until Normal mode.
Unsaved buffers survive the jump; their line numbers may have shifted since the build.
Opening a preview always allows reading; locating requires a saved, current build because SyncTeX describes built source.
Optional **Browser PDF follows cursor** only moves an existing reader for this paper.

The reader follows complete PDFs, including live builds.
On disconnection the browser keeps its last loaded PDF and retries, including after a stalled request.
Returning to the tab resumes session checks. Page presence expires after 90 seconds without a check;
closing a page releases it immediately when the browser delivers its departure notice.
An asleep device may therefore need `\\v`; browser presence never controls the reader's lifetime.
The small session indicator shows connection state by shape as well as colour;
press it for details. Routine connection text stays out of the toolbar.
**More options → Download PDF** saves a separate PDF for sharing or annotation.
That copy is not synchronized by Onesimus.

For a local browser reading a remote build, a standalone helper is also available:

```sh
~/vimrc/packages/webpreview.vim/bin/webpreview --host my-ssh-alias --pdf '/remote/path/main.pdf'
```

The helper uses your SSH configuration and needs Python 3 on both machines.
Complete revisions transfer through one SSH connection; interrupted transfers keep the last PDF and retry.
Ctrl-C ends this explicit standalone session. Editor-owned sessions instead end with Vim.

Browser preview now comes from the bundled, independently usable
[WebPreview.vim](packages/webpreview.vim/README.md). It contains the shared Vim
interface, PDF provider and built-in Markdown provider; Cogitatum connects its own renderer.
Its Python command is `webpreview`; Vim uses the bundled launcher without pip.
Onesimus supplies save/build and conflict policy through the package's hooks.
External PDF applications are for inspecting the final output; browser reading,
source navigation and Changes belong to WebPreview.

### Shared writing workflow

`\` opens global tools; `\\` opens the current document's actions.
The common writing layer owns source display, safe saving, conflict review, word count, spelling and focus.
Each format keeps its own renderer and source-position rules:

| Document | Preview behavior | What the reader shows |
| --- | --- | --- |
| TeX | `\\v` opens/reuses preview; F5 saves, builds and opens it | The last successful build |
| Markdown | Preview the draft without saving | The current buffer, including unsaved changes |
| Cogitatum (`.cog` / `.cog.md`) | Preview the inquiry without saving | The current buffer, with cursor following and return-to-source |

Use `\\v` to open/reuse preview in all three formats; `\\s` saves only the current document.
`\\o` opens More tools, including formatting, disk comparison, and preview controls.
`\\m` reads the formula at the cursor in TeX, Markdown, and Cogitatum.
Previewing Markdown or Cogitatum never saves it.
Switching buffers keeps its reader available; Vim owns the preview process.
Markdown's browser URL uses the shared hostname, including over Termius → Zellij.

Cogitatum is optional: declare `vim-cogitatum` in `custom/plugins.vim`
(see the example there) and build its preview.
Onesimus enables its ALE server and highlights inquiry fences in Markdown.
Its document menu adds outline/names, inquiry problems, and **Terminal Reading (saved file)**, with **Terminal Map** under More tools.
Reading updates on saves; opening it again reuses the same terminal.
A Markdown buffer containing `cog` fences also offers **Preview inquiry fences**,
so the whole Markdown document and the inquiry inside it remain distinct reading choices.
Return-to-source waits during typing or selection, preserves unsaved edits, and opens the target fold.
Selecting Reading text and pressing **Select in source** uses the same literal-match Visual selection as TeX.
Markdown whole-document preview uses the same Locate/Select in source rules and
keeps live drafts, source ranges, local images and math inside WebPreview.vim.
Markdown parsing defaults to remark with source-positioned MDAST; markdown-it
remains an optional build profile. KaTeX typesets formulas, and all browser assets
are bundled. See [WebPreview's product boundaries and extension API](packages/webpreview.vim/README.md).
The standalone Markdown preview plugin and its compatibility adapter are removed.
Inquiry fences keep Cogitatum's source navigation and terminal Reading/Map.
The Cogitatum preview accepts the configured relay hostname while keeping its listener on loopback.

BibTeX gets guarded save/check/compare actions and no prose sentence reflow.
Native word counts include markup and approximate CJK boundaries.

Markdown, TeX, Cogitatum and plain-text drafts use **soft screen wrapping**:
`textwidth=0`, `wrapmargin=0`, and no automatic text/comment reflow.
This policy is reapplied after EditorConfig, including `:EditorConfigReload`;
its indentation settings still apply.
`↳` marks a screen continuation, not a newline in the file.
Screen wrapping prefers whitespace, keeping punctuation with its word.
Onesimus replaces Vim's default `breakat` with spaces and tabs; an already
customized value is preserved. This option is global to Vim.
Wrapped list items retain their hanging indent.
Vertical arrows follow screen rows in Normal, Insert and Visual modes, including on narrow terminals.
Sentence/paragraph source line breaks remain under the author's control.
Arrow Up/Down follow screen rows; `j`/`k` follow physical source lines.
To hide continuation marks, use `:setlocal showbreak=`.

Treat three layouts separately: the screen fits the current window;
source newlines organize your argument; the Markdown renderer or TeX engine
lays out the published document.
For source, put a sentence on its own line and split a long sentence at a
meaningful clause **where the format permits it**.
Existing clause breaks are worth keeping even when a formatter could fit more
words on the line.
Use Enter deliberately in prose; `)` / `(` and `cis` use Vim's native
sentence rules, which are not a Chinese or English grammar parser.
`gq` is an explicit source rewrite, not a screen-wrap command;
with `textwidth=0`, native Vim still formats to the window width or 79 columns.
A filetype's `formatexpr` (such as VimTeX's) may replace that behavior.

Punctuation is evidence for a boundary, not its definition:
`Dr. Li`, `3.14`, lists such as “red, green, and blue”, and punctuation inside
links/code/math must not be split mechanically.
Vim's `linebreak`/`breakat` do not rank sentence, semicolon, and comma breaks;
`breakat` is global and cannot specify Unicode punctuation in UTF-8.
Long CJK runs and long URLs can still break at the available screen edge.
Adding source newlines between adjacent Chinese characters can introduce
rendered whitespace, depending on the Markdown renderer or TeX setup.
Keep lists, hard breaks, code, commands, math, and `%` comments intact.
Do not insert invisible characters or TeX `\\` merely to improve Vim's view.

On macOS, `brew install latexindent` supplies the formatter with its Perl dependencies.
Onesimus prefers that packaged executable when available; explicit ALE executable overrides still win.
F6 uses the configured markup formatter (Prettier for Markdown, latexindent
for TeX), without generic trailing-space or trailing-line removal afterwards.
That protects Markdown's two-space hard breaks and literal code/verbatim spaces.
Prettier defaults to `proseWrap: "preserve"`; a project's explicit
`proseWrap: "always"` will still reflow, and `"never"` will join prose lines.
Project formatter settings and EditorConfig save hooks remain effective:
for Markdown, avoid `trim_trailing_whitespace = true` if you use two-space breaks.
Opening, typing, and focus toggles do not run a formatter; F6 changes the buffer
for review and does not save it.

`<Leader>tw` / `:WPModeToggle` changes only the view, with or without Goyo and
Limelight; it never changes `textwidth`, `formatoptions`, or spelling choices.
Native focus ends when leaving its buffer/window and restores that view.
Goyo retains its own tab lifecycle; exiting Goyo also clears Onesimus focus.
Previously enabled Goyo/Limelight remain user-owned.

`\n` (Sentence lines) runs a separate TeX-aware
migration on the current buffer through `latexindent -m`; it never saves,
is never tied to F6/open/save,
and must be reviewed for abbreviations and unusual math before F5 accepts it.
It may also normalize ordinary TeX indentation. The bundled profile preserves
repeated spaces and blank lines. A formatter failure leaves both buffer and
disk untouched; `latexindent --version` exposes missing Perl modules on
installations whose executable exists but cannot run.

The sentence action is a heuristic migration, not general semantic understanding:
its bundled profile can join existing clause lines before splitting sentences.
Use it for deliberate migration, not routine maintenance of already structured
prose; leave authored clause breaks alone during ordinary editing.
Syntax-aware sentence formatters (such as Panache's semantic mode) can preserve
existing breaks, but still need abbreviation/language rules and may normalize
other markup.
Model-based SemBr can infer clauses without punctuation, at the cost of model
loading and inference; its documented non-English support is still incomplete.
Neither supplies Vim's screen-wrap algorithm, so Onesimus does not run them on
keystrokes or replace the existing project formatter.
See the [Vim options reference](https://vimhelp.org/options.txt.html#linebreak),
[Semantic Line Breaks](https://sembr.org/),
[Prettier prose wrapping](https://prettier.io/docs/options#prose-wrap),
[latexindent sentence rules](https://latexindentpl.readthedocs.io/en/latest/sec-the-m-switch.html#onesentenceperline-modifying-line-breaks-for-sentences),
[Panache semantic mode](https://panache.bz/changelog.html), and
[SemBr's model and language limitations](https://github.com/admk/sembr).

MacVim and mobile terminals share this automatic formula reading without a
terminal graphics protocol. Markdown and Cogitatum use the same source display;
terminal Reading/Map remain textual. Each browser renderer provides the complete
document preview; TeX uses its compiled PDF.

If Zellij leaves coloured strips at line ends after scrolling or resizing,
`Ctrl-L` (also under the View menu as “Redraw terminal display”) repaints the
screen. Onesimus disables Vim's BCE capability inside Zellij to avoid the
known stale end-of-line background bug; upgrading Zellij and fully restarting
its server/session is still recommended.

The built-in TeX guide also records the dash convention behind ChkTeX warning
8: `-` for a compound, `--` for a range or peer relationship, and `---` for a
prose dash. Repeated intentional names such as `Jordan--Hölder` belong in the
paper's `.chktexrc`, because ChkTeX cannot infer that semantics.

CJK support has two layers. The always-available layer is Onesimus plus native
Vim: `formatoptions+=mM`, linebreak/breakindent, CJK-safe joining, and
full-width `%` pairs such as `（）`, `「」`, `【】`, and `《》`. With
vim-surround, `ysiwq` and `ysiwQ` produce `「…」` and `『…』`.

Spacing and punctuation between Chinese and Latin text come from
AutoCorrect (`brew install autocorrect`): ALE marks lines such as
`在Vim中排版,很好用` in TeX, Markdown and plain text, and F6 applies the fix.
Math, commands, citations and Markdown code blocks are left alone.

Only word segmentation comes from jieba.vim. Its Python/Rust bridge stays
completely unloaded until a buffer contains Han text. Once ready, `w/W`,
`b/B`, `e/E`, `ge/gE`, `iw/iW`, and `aw/aW` become
Chinese-segmentation-aware. Pure ASCII editing retains native Vim behavior; if
the backend cannot load, Onesimus leaves every motion untouched.

By default the lazy loader is content-driven in every filetype, so Chinese in
source comments still gets segmented while an ASCII Markdown file pays no
jieba startup cost. To restrict automatic activation to Markdown, set this
before sourcing `init.vim` (the explicit `:OnesimusJiebaEnable` command still
works anywhere):

```vim
let g:onesimus_jieba_filetypes = ['markdown']
```

Markdown uses [mdtoc.vim](https://github.com/BaksiLi/mdtoc.vim): place the
cursor below the document title and run `:MdToc` to insert a table of contents.
After changing headings, run `:MdTocUpdate`, save, and press `<F5>` to preview.
Updates are explicit; set `g:vmt_auto_update_on_save = 1` to opt into updates
on save. `:MdTocRemove` removes the generated table.

### Typesetting and writing conventions

Onesimus takes typographic and wording choices from published conventions, so
TeX, Markdown and Cogitatum behave alike.

| Convention | Where Onesimus uses it |
| --- | --- |
| [Unicode TR #25](https://www.unicode.org/reports/tr25/), [UAX #11](https://www.unicode.org/reports/tr11/), [SI Brochure](https://www.bipm.org/en/publications/si-brochure) | In-place formulas through texinsitu.vim: `−` for minus, Vim's own cell widths, a no-break space before units |
| [UAX #14](https://www.unicode.org/reports/tr14/), line breaking | Soft wrapping keeps closing punctuation beside the formula before it |
| W3C [clreq](https://www.w3.org/TR/clreq/), Chinese text layout | Spacing and punctuation between Chinese and Latin text: [AutoCorrect](https://github.com/huacnlee/autocorrect) lints TeX, Markdown and plain text through ALE, and F6 fixes it (code blocks are left alone; a project's `.autocorrectrc` wins) |
| [Unicode TR #36](https://www.unicode.org/reports/tr36/) and [UTS #39](https://www.unicode.org/reports/tr39/) | Every window marks no-break spaces, soft hyphens, zero-width and bidirectional controls, so edits shared with a harness never differ invisibly |
| [WCAG 2.2](https://www.w3.org/TR/WCAG22/), 1.4.1, 1.4.3 and 1.4.11 | The bundled schemes keep text the writer reads (comments, folds, menus, search) at 4.5:1 and informative marks (line numbers, signs) at 3:1; `tests/themes.vim` checks it. Diagnostics: signs carry severity (with `E`/`W` in the text, never colour alone), and the message appears only on the cursor line, in comment ink |
| [Apple Style Guide](https://support.apple.com/guide/applestyleguide/welcome/web), [Microsoft Writing Style Guide](https://learn.microsoft.com/style-guide/welcome/) | Menu, notification and preview wording: sentence case, `…` for actions that ask for more, key names such as Command-F |
| ISO 80000-2, APS *Physical Review Style and Notation Guide* | Manuscript notation, checked in the PDF where TeX sets the type: italic variables, upright constants and units |

## Local Usage Journal

Onesimus records adoption of its own stable actions so old features can be
retired with evidence. The journal is enabled by default and is strictly
local: it stores action IDs, eligibility, coarse filetypes, and timestamps.
It never stores filenames, directories, buffer content, commands, queries, or
host information, and it has no network code.

- `:OnesimusStats` opens the dashboard
- `:OnesimusStatsPath` shows the journal directory
- `:OnesimusStatsReset!` deletes the local journals
- `:OnesimusStatsDisable` disables recording for the current Vim process

To disable it permanently, set this before sourcing `init.vim`:

```vim
let g:onesimus_usage_enabled = 0
```

Each Vim process writes its own small session file, so simultaneous Vim
instances never overwrite one another. A feature is only marked as a cold
candidate after at least 30 days and 10 sessions in which it was available;
zero use alone is not treated as evidence.

## Optional Font Glyphs

The status line uses no special glyphs. If the terminal font contains Nerd
Font icons, Clap can show them:

```vim
let g:clap_enable_icon = 1
```

## Configuration Structure

Personal plugin declarations live in an ignored file, so updating Onesimus
does not compete with local choices:

```bash
cp custom/plugins.vim.example custom/plugins.vim
```

Personal options load earlier from the ignored `custom/settings.vim`:

```bash
cp custom/settings.vim.example custom/settings.vim
```

The default themes are Gruvbox for terminals and Nord for MacVim. Both ship in
`packages/themes` as plain `:highlight` lists that
`scripts/build_themes.vim` generates from pinned upstream commits and checks
group by group. This avoids the ~30 ms first `:hi clear` that MacVim's binary
pays. The status and tab lines are Vim's own (`functions/Statusline.vim`):
vim-airline cost about 25 ms of every start. The tab line appears only when
more than one buffer or tab page is open, which leaves the row to the text on
a phone. Enable `g:onesimus_extra_themes = 1` in that settings file to add
Seoul256 and Monokai,
or `g:onesimus_developer_plugins = 1` for HelpfulVersion and Vader. Tabular loads
on the first `:Tabularize`; date increments remain available by default.
Our independent editor tools use a capability name followed by `.vim`:
`mdtoc.vim` for Markdown tables of contents, `webpreview.vim` for browser
previews, and `texinsitu.vim` for formulas in place. `vim-cogitatum` keeps its
established language-host name. Old TOC commands and document markers remain
compatible.

Optional self-maintained plugins may use `OnesimusPlugin(repo, options)` in
`custom/plugins.vim` to share the reviewed pin. Set
`g:onesimus_plugin_overrides` there to map a plugin name to a local checkout.
Local overrides are never updated or built by the remote plugin updater;
build those projects explicitly. The example documents Cogitatum's matching
CLI and the currently local-only texinsitu checkout.

```
.
├── custom/         - Local plugin declarations and their example
├── config/         - Distribution policies and plugin lock loader
├── snippets/       - UltiSnips snippets
├── functions/      - Custom functions
├── plugconf/       - Plugin configurations
├── .editorconfig   - Repository editing conventions
├── init.vim        - Main configuration
├── automated.vim   - System setup
├── plugins.lock.json - Reviewed remote plugin revisions
└── README.md       - This file
```
